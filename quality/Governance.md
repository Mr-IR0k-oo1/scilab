# Governance

## Project Structure

```
Scilab Studio
├── Core Team
│   ├── Project Lead
│   ├── Tech Lead
│   └── Design Lead
├── Contributors
│   ├── Core Contributors (write access)
│   └── Community Contributors (PR access)
└── Advisory Board
    └── FOSSEE Representatives
```

## Roles

### Project Lead
- Overall project direction.
- Final decision on architecture.
- Release management.
- Community management.

### Tech Lead
- Technical architecture.
- Code quality standards.
- Review process.
- Performance standards.

### Design Lead
- UI/UX design.
- Design language.
- Accessibility.
- User research.

### Core Contributors
- Review and merge PRs.
- Write to core modules.
- Participate in RFC process.
- Mentor community contributors.

### Community Contributors
- Submit PRs.
- Report issues.
- Improve documentation.
- Build plugins and widgets.

## Decision Making

### Consensus
- Most decisions are made by consensus.
- Core team discusses on GitHub Issues/Discussions.
- Project Lead makes final call if consensus fails.

### RFC Process
- Significant changes require an RFC.
- RFC is open for 1 week for comments.
- Core team reviews and decides.
- Accepted RFCs are implemented.

### Voting
- Used only for contentious decisions.
- Core team votes (1 person = 1 vote).
- Simple majority wins.
- Project Lead has tie-breaking vote.

## Pull Request Process

### For Contributors
1. Fork the repository.
2. Create a feature branch.
3. Make changes.
4. Write tests.
5. Update documentation.
6. Submit PR.
7. Respond to review comments.
8. PR is merged.

### For Reviewers
1. Review code for correctness.
2. Check test coverage.
3. Verify documentation.
4. Test on your platform.
5. Approve or request changes.
6. Merge when approved.

## Issue Management

### Labels
| Label | Description |
|-------|-------------|
| `bug` | Bug report |
| `feature` | Feature request |
| `enhancement` | Improvement to existing feature |
| `documentation` | Documentation issue |
| `good first issue` | Good for newcomers |
| `help wanted` | Needs community help |
| `blocked` | Blocked by another issue |
| `wontfix` | Will not be fixed |

### Milestones
- Each release has a milestone.
- Issues are assigned to milestones.
- Milestones have due dates.

## Communication

| Channel | Purpose |
|---------|---------|
| GitHub Issues | Bug reports, feature requests |
| GitHub Discussions | General discussion, Q&A |
| Discord | Real-time chat, community |
| Mailing List | Announcements, releases |
